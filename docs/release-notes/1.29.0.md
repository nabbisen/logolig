# 1.29.0

1.29.0 is about being readable and robust: larger and clearer text and controls, a setting that enlarges the whole interface, plain-language options, and safer handling of the files you give it.

## Highlights

- **Larger, clearer text and controls.** A fixed scale of text sizes (nothing smaller than 13 px), contrast of at least 7:1 for text and 3:1 for the borders and marks of controls in both themes, and larger click targets.
- **Interface size in Settings.** Normal, Large (125 %) or Extra large (150 %) scales text and buttons together; the choice is saved.
- **The Customize page says what each option does**, in plain words, with the technical names kept in brackets.
- **Safer file handling.** The content of a file, not its extension, decides what it is; oversized or unusual files are refused with a clear message, and a refused file no longer costs you the previous result.
- **"System" theme follows your operating system** where it reports a light or dark choice.
- **The Sharp preset now keeps corners** (its corner setting had been set the wrong way). SVGs made with Sharp differ from those of 1.28.0.

## Changes by area

### Readable interface

- **Text sizes.** Five steps: 13 px (only the footer), 14, 16, 20 and 28; icons are 16 and 22 px. Labels, button text and messages are 16 px; supporting lines, the details of a result and the navigation labels are 14 px.
- **Contrast.** In Light and Dark, text reaches at least 7:1 against what it is drawn on (secondary text included), and the borders and marks of controls reach at least 3:1. The selection marks use the accent colour in both themes. Exempt: the edges of cards that only frame other content, the preview's drawings of a browser tab and a phone, disabled controls, and the focus ring (which is measured separately). Measured with the automated tests on a software-rendered picture of every screen, not in a real window.
- **Click targets.** The main buttons (Download all, Back, the navigation items, in both languages) are at least 44 px high; other buttons and text fields are at least 32 px. Two controls that belong to the interface toolkit stay a little smaller (the checkbox rows at about 30 px, the notification's close button at about 24 px); the notification can also be closed with Esc.
- **Interface size.** Settings has a new "Interface size" group: Normal, Large (125 %) or Extra large (150 %). The whole interface scales, the choice is saved and read back at start, and the window cannot be made smaller than a usable size (360 × 480). At Extra large the narrow ("phone") layout is used in a window that shows the wide layout at Normal; choosing a step with the arrow keys keeps the focus on the group while the layout switches.
- **Plain-language Customize page.** Each option says what it gives you; the technical or file name stays beside it in brackets (for example the Apple home-screen icon and its file name). "Favicon" and "ICO" are explained once. The descriptions of the resize methods follow a measurement of how each handles edges. "Recommended" stands only on the default choice.

### Files

- **The content decides.** A file is recognised by what is inside it, not by its name. When the name suggests another format than the content (a JPEG named .png, for example), you get one notice, merged with the JPEG note when both apply, instead of two.
- **Limits, checked before the file is decoded:** 64 MiB per file, 8 MiB for an SVG, 16 384 pixels on a side and 50 megapixels in total. Only regular files are read (not directories, pipes or devices). A refused file gets a message that names the file (not its full path), the limit and what to do.
- **A refused file keeps your work.** If a file cannot be loaded, the previous result, its "View results →" card, the source and the screen come back as they were.

### Download all (ZIP)

- **The files in the ZIP carry the time they were made, as an exact moment.** The ZIP's basic time field has no time zone, so the application writes the UTC time there and also the standard "extended timestamp" field. `unzip` and `bsdtar` show the right local time from it (checked in two time zones). A tool that reads only the basic field (Python's `zipfile`, for one) shows the UTC time as if it were local. Windows Explorer and the macOS Archive Utility were not tested.

### Theme

- **"System" follows the operating system** where it reports a light or dark choice, including a change while the application runs. The Settings row says what it does now: "System (currently Dark)" or "System (currently Light)", and "System (not reported; using Light)" when the system gives no answer. The saved setting stays "System". The preview's Surface choice keeps the plain word "System".

### Web manifest

- **Colours are checked as you type.** `#RGB` is accepted and kept as `#RRGGBB`; a value that is not a colour is never saved or used, and the field shows an icon and a sentence beside it saying what is accepted. Names may not be empty. Earlier versions could write half-typed text into the settings file; a settings file with invalid manifest values is loaded with those values reset and one notice.

### SVG conversion presets

- **Sharp keeps corners.** The setting that decides which turns count as corners had been set the wrong way: Sharp rounded corners of about 100° to 120° more than Default does and wrote more path segments. It is corrected (a measurement on 25 test shapes is the basis). **SVGs made with Sharp now differ from those of 1.28.0**: corners of about 100° to 135° are sharper and the files are usually smaller. Default is unchanged.
- **The two labels say only what was measured.** Sharp reads "keeps corners sharp"; Photo-rich reads "keeps a little more color detail" and no longer promises gradients: a smooth gradient is flattened to one colour by every preset.

### Language

- **Every text the application shows is in the translation tables**, in English and Japanese: the error notification's title, the file chooser's title and filter name, the file count on the start screen (now "Files: N"), the two preview captions and the grayscale PNG badge. Two automatic checks keep it so.

### Under the hood

- `cargo audit` reports **0 vulnerabilities** and 11 triaged warnings. They are warnings (an unmaintained or unsound notice), not vulnerabilities: four that come through `vtracer`'s old dependency chain (compiled, but not part of the program as built: no symbol of them is in the binary), and seven through the interface and D-Bus libraries. A dependency update cleared one advisory (`url`), and the `chrono` library, which had an open "unmaintained" notice, is gone: the time stamped on the files in the "Download all" ZIP is now computed by a few lines of the application's own safe code, with no new dependency.
- Headless layout and contrast tests cover every screen at several window sizes (including the narrow ones the larger interface sizes lead to), in English and Japanese, in both themes. 523 automated tests.
- The Microsoft Store manifest version is now derived from the workspace version by a checked script.

### Packaging

- The Linux package metadata for software centres (the AppStream MetaInfo and the desktop entry) is in `packaging/linux/` and is validated in CI. This is preparation only: **Logolig is not announced as available in any software centre.**
- The Arch Linux (AUR) packaging files were removed from the repository.

## Known limitations

- **Screen readers are not supported** (the interface toolkit, iced 0.14, exposes no accessibility tree).
- **Windows and macOS were not exercised** in this release cycle. The keyboard and size checks were made on Linux (niri compositor, Wayland) with the English interface.
- **The new Japanese texts have not had a native review.**
- **The technical detail inside an error message** (for example the operating system's own text) **stays in English** next to a translated sentence.
- **The minimum window size was verified from the source, not in a window.**
- After a **mouse click** on a disclosure header ("Advanced settings", the preview toggle) or on an Interface size option, the focus ring stays until the next click elsewhere or Tab.
- After Enter on a navigation item, no control has the focus; the next Tab starts at the first control.
- **Text inside an SVG is not drawn.**
- **"System" follows the operating system only where it reports a preference**; otherwise Light is used.
- On **X11** the operating system's own display scaling was not followed when last checked; the Interface size setting is the way to enlarge the interface. It was exercised on Wayland only.
- Contrast and sizes were measured on the software renderer, not on every real display.
- **ZIP file times:** extractors that ignore the extended timestamp show the UTC time as local; Windows Explorer, the macOS Archive Utility and 7-Zip were not tested. After January 2038 the extended field stays at its 32-bit limit while the basic field keeps the right date.

## Upgrade notes

- **Saved settings** from 1.28.0 and earlier load as before. A new field, the interface size, is added when settings are next saved; a file without it loads as Normal, and so does an unknown value.
- **For users of the `logolig` and `logolig-i18n` libraries.** The rule of 1.x stands: **a public item is not removed or renamed**. These are **source-compatibility notes**: neither `MessageKey` nor `AppError` is `#[non_exhaustive]` yet, so an exhaustive `match` on them in your code needs the new arms.
  - **`MessageKey`** gained 28 variants: for the file rules and their notices (5), the web manifest checks (5), the System theme row (2), the plain-language Customize texts (4), the Interface size setting (5) and the texts that were written in the code (7).
  - **`AppError`** gained three variants: `InputTooLarge`, `ImageTooLarge` and `ManifestInvalid` (with constructors `input_too_large`, `image_too_large` and `manifest_invalid`).
  - **`PersistedSettings`** has a new public field `interface_size` of the new public type `InterfaceSize` (Normal, Large, ExtraLarge): code that builds `PersistedSettings` with a struct literal needs the new field or `..Default::default()`. A settings file without the field loads as Normal.
  - **New public items:** `InterfaceSize`, `FormatNote`, `Ingested`, `services::ingest::{ingest_noted, ingest_bytes_noted}`, the limits `MAX_INPUT_BYTES`, `MAX_SVG_BYTES`, `MAX_SIDE` and `MAX_PIXELS`, and `WebManifestSettings::{normalize_color, normalize_text, sanitized}`. `ingest` and `ingest_bytes` keep their signatures.
  - **Deprecated** (kept until the next major version): `MessageKey::ThemeSystem` (the Settings row now uses two new texts). The deprecations of 1.28.0 stand.
  - **Behaviour:** `ingest` now decides the format from the content, enforces the limits above, and reads regular files only; its error texts carry the file name, not the path. `vectorize` with `VtracerPreset::Sharp` produces different SVGs than before.
