# 1.30.0

1.30.0 is about reaching more systems honestly: the start screen no longer promises what some systems cannot deliver, the message after saving makes sense inside a Flatpak sandbox, and the project now builds and tests itself on Windows. There is no change to what the application produces.

## Highlights

- **The start screen says what is true on every system.** It now leads with the click ("Choose a PNG, SVG, WebP, or JPEG"; "Click anywhere here, or drop a file if your system allows it."), because file drops are not delivered on some systems, for example some Wayland setups. Dropping a file works exactly as before where the system delivers it.
- **The message after saving shows the file name** instead of an internal `/run/user/…/doc/…` path when the file chooser is a portal (which is what a Flatpak uses). On other systems the full path is shown as before.
- **The project builds and runs its tests on Windows** in a separate, non-blocking CI workflow, and produces an unsigned Microsoft Store package as a workflow artifact. **The application has never been started on Windows.**

## Changes by area

### Start screen

- **Click first.** The Empty screen's headline is "Choose a PNG, SVG, WebP, or JPEG" and its second line is "Click anywhere here, or drop a file if your system allows it." The Japanese lines say the same ("PNG / SVG / WebP / JPEG を選択"; "クリックして選べます。対応するシステムではドロップも可能です。").
- **The "no file dialog" notice no longer advises dragging a file.** It now says to install a desktop portal with a file dialog (for example `xdg-desktop-portal-gtk`) or, if the system allows it, to drop a file onto the window. The Japanese notice is changed the same way.
- **The drop itself is unchanged**: no code that handles a dropped file was touched. Where a system delivers drops, they work as in 1.29.0; where it does not, the click always works.
- **Fit.** A new automatic layout test checks that the three texts of the start screen's card are inside the card and fully visible at eleven window sizes, in English and Japanese, with and without a history card.

### Saving files

- **A portal path is shown as the file name.** After "Download" or "Download all", the message shows the file name when the path lies under the document portal (`<XDG_RUNTIME_DIR>/doc/…`, the form a Flatpak's file chooser returns). Any other path, and every path on Windows and macOS, is shown in full as before. The file is written where you chose in both cases; only the text of the message changed.

### Language

- **"favicon" is written in Latin letters** in the Japanese title of the file chooser, as everywhere else in the Japanese interface.

### Under the hood

- **Windows in CI.** A separate workflow (`windows-package.yml`; not part of the main CI, nothing requires it) builds the application in release mode on a Windows runner, runs the whole test suite (**525 tests passed on Windows, 0 failed**; the Linux total is 536, the 11 that exist only on Linux are not counted there), packs an **unsigned** Microsoft Store package and keeps it as a workflow artifact for the maintainer. The package is unsigned on purpose (the Store signs on ingestion), so it cannot be installed locally. The workflow runs by hand, on a version tag and when the workflow file itself changes. **This is evidence about the build and the tests, not a statement that Windows is supported: the application has never been started on Windows by a person.**
- **Line endings.** The repository now has a `.gitattributes` so that every checkout, on every platform, uses LF line endings (the Microsoft Store manifest is the one file kept byte for byte). Two source-scanning checks of the test suite were made independent of the line ending; one of them had been cutting source files short on a CRLF checkout, so it silently scanned less there. Both are tested with LF and CRLF text, and the whole suite also passes on a CRLF copy of the sources.
- **Dependencies.** `cargo audit` reports **0 vulnerabilities** and 11 triaged warnings. They are warnings (an unmaintained or unsound notice), not vulnerabilities: four come through `vtracer`'s old dependency chain (compiled, but not part of the program as built: no symbol of them is in the binary), and seven through the interface and D-Bus libraries. None is reachable from the application's code as measured.
- **Tests.** 536 automated tests on Linux (1.29.0: 523).
- **Packaging.** The Linux package metadata for software centres (the AppStream MetaInfo and the desktop entry) is in `packaging/linux/` and validated in CI. The project is being prepared for Flathub; **Logolig is not announced as available in any software centre.**

## Known limitations

- **Screen readers are not supported** (the interface toolkit, iced 0.14, exposes no accessibility tree).
- **File drops do not arrive on some systems**: on one tested Wayland setup (the plain build and the Flatpak) dropping a file onto the window does nothing, a limit of the interface toolkit on that system. The click always works, and the start screen now says so.
- **Windows and macOS were never run by a person.** Windows is built and tested in CI (see above); macOS is neither built nor tested. The keyboard and size checks of 1.29.0 were made on Linux (niri compositor, Wayland) with the English interface.
- **At the smallest window (360 × 480), with a history card on Home, the "Accepted: …" line of the start screen disappears.** An automatic test pins this; it is unchanged from 1.29.0, and the same information is in the file chooser and the documentation.
- **The Japanese texts changed in this release** (the start screen's two lines and the "no file dialog" notice) **have not had a native review.**
- **The minimum window size was verified from the source, not in a window.**
- **The technical detail inside an error message** (for example the operating system's own text) **stays in English** next to a translated sentence.
- **Text inside an SVG is not drawn.**
- **The Windows package is unsigned** and cannot be installed locally; the Store signs it on ingestion.
- The other limitations of 1.29.0 (the focus ring after a mouse click on a disclosure header or an Interface size option, no focused control after Enter on a navigation item, "System" theme following the operating system only where it reports a preference, the operating system's own display scaling not followed on X11 when last checked, contrast measured on the software renderer, ZIP time stamps in extractors that ignore the extended field) are unchanged: nothing in those areas was touched.

## Upgrade notes

- **Saved settings** from 1.29.0 and earlier load as before; no setting was added or changed.
- **For users of the `logolig` and `logolig-i18n` libraries.** The rule of 1.x stands: **a public item is not removed or renamed**. In this release there is **no change to the public API** of either crate: the source of `logolig` and `logolig-i18n` is unchanged (no new, removed or deprecated `MessageKey`, `AppError` variant or other public item); only the text of three entries of the translation tables (in English and in Japanese) and the Japanese file chooser title changed. A library user who shows these texts will see the new wording. The deprecations of 1.28.0 and 1.29.0 stand.
