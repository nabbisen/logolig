## What "done" means (the rule, from RFC 034 req. 3)

In **Light and Dark** (System resolves to one of them):
1. **Every text colour reaches at least 7:1 (WCAG AAA) against the surface it is drawn on**, including secondary text; secondary text becomes a **solid colour** (no `0.6`-alpha body colour: `colors::muted_text` today).
2. **White (or the button's text colour) on the primary button reaches 7:1**: the primary colour is darkened (today `#5865F2`, 4.61:1 with white; a blue near `#3C47B8` gives about 7.5:1: **measure and choose the lightest that passes, keeping the same hue family**), for every state that is meant to be read: rest, hover, pressed; a disabled state is exempt from the ratio but must stay distinguishable from enabled.
3. **Borders and marks of controls reach 3:1** against the colours next to them (WCAG 1.4.11): button outlines, text-input borders, the unchecked checkbox and radio outlines (snora guarantees its own at 3:1: verify, do not assume), the focus ring (snora's rule), the navigation accent bar (`colors::nav_accent`, chosen in J10 at 3.4:1 / 2.5:1 against the sidebar: re-measure against **both** neighbours and raise it), card edges that are the only thing marking a control.
4. Caption text (13 px, RFC 034 D1) is never the only carrier of information: report where it is (no change needed unless a caption is the sole instruction).

## 1. Work (tests first)

1. A small pure module for the ratio (`ui/contrast.rs` or test-support if it is only used by tests; **the production code should also be able to assert**: choose, say why). Pairs inventory as data (a list of named pairs per theme built from the actual functions, so a new colour that is added to the inventory test cannot be forgotten silently: a source test that every `fn ... -> Color` in `ui/colors.rs` appears in the inventory).
2. The palette: **one place** defines the application's Light and Dark `Theme` (iced `Theme::custom` with a `Palette`, or the smallest equivalent: say which and why; today `resolve_theme` returns iced's `Theme::Light`/`Theme::Dark`). Keep the hue family and the look; change values only as far as the rule needs. Text colours: the background-text pairs of iced's extended palette are generated from the palette; **measure what they give**, and where a tier's text falls under 7:1, derive our own colour in `colors.rs` instead of using the tier (document which tiers are not used for text).
3. `colors::muted_text` and every other alpha-blended text colour become solid colours computed against **the actual background they sit on** (page, card/weak tier, toast, disabled group): list the backgrounds in the inventory. Contrast is checked against each.
4. The primary button style (and any filled-accent surface: the "Download all" button, the active navigation fill, toast accents if any) uses the new primary; text on it stays white or black by whichever passes (prefer white).
5. Non-text: raise the weakest borders/marks to 3:1 where they carry meaning (listed in the inventory with the before/after ratios). Decorative edges (a card's hairline around other content) are exempt: say which you treated as decorative.
6. Docs: `docs/src/ui-a11y.md` gets the contrast facts **as measured** (the table of pairs and ratios in a short form, the rule, the exemptions) and the README's accessibility sentence is unchanged; `docs/src/functional-spec.md` only if it names a colour. RFC 018's closing note about display scaling is unaffected.

## 2. Evidence, acceptance, prohibited

Review request `.git-exclude/review-request/rfc-034-j21-contrast/README.md` (report only its path): the inventory with **before and after ratios for every pair in both themes** (a table), the red failure list, the pictures (their paths, your description of each difference), the selection-mark finding with pictures, where you used a derived colour instead of an iced tier, test-list diff (named additions, none removed), gates and CI per commit. Acceptance: every text pair ≥ 7:1 and every meaning-carrying non-text pair ≥ 3:1 in Light and Dark, proven by a test that can fail; no layout change; no new package; the look recognisably the same family. Prohibited: a fourth theme or a theme setting; changing sizes, spacing or text; the snora `design` feature; loosening the thresholds or excluding a pair without listing it as an exemption with a reason; any `#[allow]` beyond the existing patterns; a red push; absolute `cd`; tags, force-push or history rewriting.
