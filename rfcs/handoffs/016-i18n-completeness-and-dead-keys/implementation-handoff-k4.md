# Developer Handoff — RFC 016 (narrowed) job K4: no hardcoded user-visible text, and a guard that keeps it so

Role and rules as always (`.git-exclude/roles/*`, `.git-exclude/rules/*`; GUI Evidence and Test Optimization rules; Rust 2024, tests in separate files, English only in code and documents, `unsafe` forbidden; **relative paths with `cd`, or none**; **gates chained with `&&`, exit status tested before any commit or push**; audit 0 / 12; CI watched after each push; no tags, force-push or history rewriting). Governing text: [RFC 016](../../done/016-i18n-completeness-and-dead-keys.md) **with its "Amendment 2026-11-22: SemVer narrows the dead-key cleanup"** and "Decisions 2026-11-22". Review of J24b: `.git-exclude/reviewed/rfc-034-j24b-review-2026-11-25.md`.

**What is in and what is out (read this first).** `MessageKey` is a public, exhaustive enum of the published `logolig` crate: **removing a variant is not allowed in 1.x** (my own SemVer rule; removal is on the 2.0 list in `ROADMAP.md`). So this job **does not remove or rename any key**. It does two things: (1) every user-visible string the application shows comes from the dictionary, in English and Japanese; (2) a **guard test** that fails when a new hardcoded alphabetic literal reaches the UI or a new key is added and never used. The RFC's original "delete the 41 unused keys" and its CI grep rule are **out**: the first by SemVer, the second replaced by the source test (it runs in `cargo test`, so in CI, with no new tooling).

Owner philosophy: clean, safe and secure, robust design; users must not be confused. A Japanese user who sees one English title in an error toast is confused and sees an unfinished product.

## 1. Work (tests first, shown failing before)

1. **The audit table first** (evidence, then the fix). Include `rfd` dialog titles, filter names and default file names (`task_queue.rs`: the file chooser title, `"Images"`, `"ZIP"`, the save names: a default file name such as `favicon.zip` is a file name, not prose: say which you treat as exempt and why), the history card count text, window titles and the `Logolig` name (a product name is exempt), tooltips.
2. **Fix every non-exempt literal** with a key in both languages: `ToastErrorTitle` for "Operation failed" (and any sibling), dialog titles and filter names as keys, the plural-free count text with a `{count}` placeholder. **Texts:** plain, in the file's existing style; the Japanese pairs go to `.git-exclude/tmp/ja-review-1.29.0.md` (not blocking); the half-width-space habit is **not swept** (owner's open decision: follow the file as it is).
3. **The guards** (two tests, one file or two under `crates/app/src/` per the project's test layout; the dead-key test needs the keys: it may live in the `logolig-i18n` or core crate tests if that is the natural place for reading `message_key.rs`; choose and say why): hardcoded-literal scan and unused-key scan, with the fixtures as data. Both must run on every `cargo test` and be fast.
4. **No removal, no rename** of any key or variant; **no new `#[allow]`** beyond the existing deprecation pattern; the new keys are an accepted source-compatibility note for the release notes (count them).
5. Docs: `docs/src/architecture.md` or `functional-spec.md` where the i18n rule is stated (every user-visible string is a `MessageKey`; the guard); nothing else.
6. **No real-window run** (the matrix and key parity cover it; the release pass has the Japanese interface).
