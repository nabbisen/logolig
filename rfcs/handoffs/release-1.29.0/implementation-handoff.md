2. **Release notes:** new `docs/release-notes/1.29.0.md`, English, **no RFC numbers**, same structure as 1.28.0's (Highlights 3–6 bullets, Changes by area, Known limitations, Upgrade notes). **Every statement must be supported by a review file (`.git-exclude/reviewed/`), a test or a measured number; leave out and report anything you cannot support.** The title is the bare version (`# 1.29.0`: the release title convention). Content (verify each against `git log 1.28.0..HEAD` and the reviews):
   - **Readable for older users:** text sizes (caption 13, secondary 14, body 16, title 20, heading 28; icons 16/22), contrast (7:1 for text, 3:1 for marks and borders, both themes), larger click targets (44/32), **Interface size** in Settings (Normal / Large / Extra large = 100 / 125 / 150 %), the window cannot be made smaller than a usable size, plain-language Customize labels (what each option does, the algorithm names kept in brackets), the focus stays on the size group while the layout switches.
   - **Safer file handling:** the file's content decides the type (not its extension); limits: 64 MiB per file, 8 MiB for an SVG, 16 384 px per side, 50 megapixels, regular files only; a rejected file leaves the previous result and screen in place; one merged notice for several rejected files; file names only (no full paths) in messages.
   - **System theme:** "System" follows the operating system's light/dark choice where it reports one; the setting shows "System (currently Dark)" or "(not reported; using Light)".
   - **Web manifest:** colours are validated as typed (`#RGB` is accepted and stored as `#RRGGBB`), an invalid colour is never saved and the field shows what is wrong beside it.
   - **Sharp preset (a visible output change):** the Sharp preset's corner setting was set the wrong way; it now keeps corners (corners of about 100–135° are sharper, and the files are usually smaller). **SVGs made with Sharp differ from 1.28.0's.** The Sharp and Photo-rich labels now say only what was measured (the Photo-rich label no longer promises gradients: a smooth gradient is flattened by every preset). `Default` is unchanged.
   - **Language:** every user-visible text is now in the translation tables (the error toast title, the file chooser's title and filter, the file count, two preview captions, the PNG badge); two automatic checks keep it so.
   - **Under the hood:** `cargo audit` 0 vulnerabilities, 12 triaged warnings (unchanged: 1 `chrono`, 4 through `vtracer`'s old dependency chain, 7 through iced and zbus: say plainly that these are warnings, not vulnerabilities, and that none is reachable from the application's code as measured); the headless layout and contrast tests; Linux metadata for software centres (the MetaInfo file and the desktop entry are in `packaging/linux/`; **do not announce Flathub as available**); the Microsoft Store manifest version is now derived from the workspace version by a checked script.
   - **Known limitations (state each):** no screen-reader support (iced 0.14 exposes no accessibility tree); Windows and macOS were not exercised in this cycle; the keyboard and size checks were made on Linux (niri compositor, Wayland), English interface; **new Japanese texts have not had a native review**; **the technical detail inside an error message (for example the operating system's own text) stays English next to a translated sentence**; the minimum window size was verified from the source, not in a window; after a mouse click on a disclosure header or on a size option the focus ring stays until the next click elsewhere or Tab; SVG text is not drawn; `System` follows the OS only where the OS reports a preference.
   - **Upgrade notes (library users):** `logolig` and `logolig-i18n` are public. Take the exact lists from the code, **not from this text**: `rg 'deprecated' crates` and `git diff 1.28.0..HEAD -- crates/core/src crates/i18n/src`. Expected: new `MessageKey` variants (K1 ingest 5, K2 manifest, K3 System-theme 2, J23 4, J24 5, K4 7) and `ThemeMode`/`AppError` variants, `InterfaceSize`, a new public field of `PersistedSettings`, `MessageKey::ThemeSystem` deprecated (kept until the next major). These are **source-compatibility notes**: neither `MessageKey` nor `AppError` is `#[non_exhaustive]` yet, so an exhaustive `match` in downstream code needs the new arms. Say the 1.x rule: a public item is not removed in 1.x.
3. Nothing else: no code, no RFC or ROADMAP edit. If you find something in the notes' list that the code does not support, **report it, do not fix it here**.
