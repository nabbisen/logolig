# Developer Handoff — RFC 037 phase B, job B1: a Windows build, the first Windows tests and an unsigned package in CI (spike first)

Role and rules as always (commits on `main`, gates chained with `&&` and their exit status tested before commit and push, `git log origin/main..` before every push, wait for CI on each commit, relative `cd`, English only, no topic branches, no tags, no force-push). Governing RFC: [RFC 037](../../accepted/037-microsoft-store-packaging-automation.md), phase B. **No version change, no release.** The project has never been built or tested on Windows: this job finds out what is true. **If the build or a test fails because of the application's code, report it with the log; do not fix application code in this job** (the architect decides what to do with each finding).

## Commit 1: the workflow `.github/workflows/windows-package.yml`
A **separate, non-blocking** workflow (not a job in `ci.yml`; job names of `ci.yml` are a contract). Same conventions as `flatpak-upstream.yml`: header comment saying what it does and does not do, `permissions: contents: read`, `timeout-minutes`, third-party actions **pinned by commit SHA with the version in a comment** (look the SHAs up and verify them; report how). Triggers: `workflow_dispatch`; push of a tag matching `[0-9]*.[0-9]*.[0-9]*`; and push to `main` that changes **only this workflow file** (so you can iterate on it; a new workflow with only `workflow_dispatch` cannot be started before it is on `main`). No `pull_request`, no secret, no signing, no certificate, no submission. On `windows-latest`, steps (the answers to the spike's questions are **printed in the log and quoted in your report**):
1. Checkout; print the runner image, OS version, `rustc -V`, `cargo -V`; install the stable toolchain as `ci.yml` does (and report whether MSRV 1.90 builds on Windows: `cargo +1.90 check`, informational).
2. `bash scripts/appx-version.sh check` (`shell: bash`; Git Bash is on the runner): the manifest's version rule on Windows too.
3. `cargo build --release --locked -p logolig-app`. **Does it build unchanged?** (the portal probe and the `cfg` gates were written but never compiled for Windows). A failure stops here: report it.
4. `cargo test --workspace --locked`, with `continue-on-error: true` **for this first stage only**, the result printed (count passed, the names of any failures). Do not skip, `#[ignore]` or adapt any test. Real failures are findings.
5. Locate **`makeappx.exe`** (look under `C:\Program Files (x86)\Windows Kits\10\bin\<version>\x64\`, take the highest version) and print its path and version. Also print whether the Windows App Certification Kit's `appcert.exe` is on the runner and where (**do not run it**; report only).
6. Stage a directory: `logolig.exe` (from `target\release`), `Assets\` and `AppxManifest.xml` from `packaging/windows/`. Print its tree.
7. `makeappx pack /d <stage> /p logolig-<workspace version>.0-unsigned.msix /o`, with its validation on (do not pass `/nv`). **What does `makeappx` say about the layout?** Print its full output. If it complains (a missing tile size, a manifest problem), report the exact message and do not change the manifest (its `Identity`, `Publisher`, tiles and other content are the Store's and mine to change).
8. Print the `.msix`'s **size and SHA-256** (`Get-FileHash`), and upload it with `actions/upload-artifact` (name with the version, `retention-days: 14`, `if-no-files-found: error`). The executable's size and SHA-256 too.
The package is **unsigned on purpose**: Partner Center signs on ingestion; it cannot be installed locally, and the docs say so.

## Prohibited
Secrets, signing, certificates, any outward action (no Store submission, no release asset, no publishing); changes to `AppxManifest.xml`, the tile images, `Publisher` or `Name`; application code, tests or `Cargo` changes (report findings instead); adding the workflow to `ci.yml` or branch-protection settings; tags; version changes; edits to `rfcs/` and `ROADMAP.md`; `#[allow]`; absolute `cd`; a repeated run to hide a failure (report every run id, including red ones).
