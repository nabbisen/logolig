## Question A — `chrono`

Its one use: `crates/app/src/task_queue.rs` `current_zip_modified_time()` (uses `Local`, `Datelike`, `Timelike`) builds a `zip::DateTime` for ZIP entries. Options to **evaluate with evidence**, not by taste:
1. **`zip`'s own `time` feature** (`zip` 9 can convert from `time::OffsetDateTime`; check what is already in the lock: `cargo tree -i time`), with `time::OffsetDateTime::now_local()`; **read its documented caveat** (on Unix, `now_local` can return an error in a multi-threaded process unless an `unsafe` cfg is set: **`unsafe` is forbidden in this workspace**; so what is the fallback: UTC? say how it behaves in the app's tokio context).
2. **UTC only, no local time:** a ZIP stores a local-time DOS date; UTC would show a time shifted by the user's offset in a file manager. How visible is that, and what do other tools do (`zip` CLI uses local time; many reproducible-build tools use a fixed time)? Is the generation time useful to the user at all (the files inside are generated now; their meaning is "just made")?
3. **A fixed timestamp** (for example 1980-01-01 00:00:00, the DOS epoch, or the date of the source file): byte-reproducible ZIPs (a plus for tests and for users who diff outputs), loses "when generated". What does `zip::DateTime::default()` give today as the fallback (`task_queue.rs`), and is that already effectively this?
4. **`std` only:** `SystemTime` → UTC civil date by a small, tested function (about 25 lines: days-from-civil); no new package; local offset not available without `libc` (unsafe) — so it is option 2 with no dependency.
5. **`jiff` or `chrono-tz`-free alternatives:** list only if they add **no more packages than they remove**; give `cargo tree` counts.
For each option: new packages added/removed (`cargo tree` before/after in a **throw-away worktree**), `cargo audit` result on that tree, behaviour (local/UTC/fixed), what a test would pin, size of the change, MSRV 1.90 compatibility. **Recommend one**, with reasons, and say what the ZIP entry times look like to the user in each case (extract a ZIP with `unzip -l` and with a file manager if one is available: report what you saw).
