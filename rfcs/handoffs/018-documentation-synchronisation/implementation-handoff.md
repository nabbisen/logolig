Role and rules as always (`.git-exclude/roles/*`, `.git-exclude/rules/*`; English only; relative paths with `cd`). Governing RFC: [RFC 018](../../done/018-documentation-synchronisation.md), **"Closing plan (2026-11-21)"** and the decisions D1/D2. Review of J14c: `.git-exclude/reviewed/rfc-027-j14c-review-2026-11-21.md`. **Documentation only: no code, no `Cargo` change.** (If you find a defect in code while reading, report it; do not fix it here.)

Owner philosophy: users must not be confused or misled; documentation is the test-design source of truth, so it must say what the program **does**, verified, not what was once intended.

**Workflow:** `main`; `git pull --ff-only`; `git log origin/main..` before every push; **one commit per document** (README, `architecture.md`, `functional-spec.md`, `export-spec.md`, `ui-a11y.md`, `rfcs/README.md` as needed); each commit message names the commit hash the document was verified against; gates are those of a docs commit (`cargo fmt --check` and `cargo doc --workspace --no-deps --locked` must still pass; the Packaging workflow must stay green); CI waited for; no tags, force-push or history rewriting.

## Method (every row)

For each row of RFC 018's table and the additions A–E of the Closing plan: **read the document, then read the code or run the program** for the fact, and write only what you verified.
